更新：2026-10-16 ｜ 产出：walk.png 128×128、idle.png 128×32
本次**没有使用扩散模型**，全部由 `star1.aseprite` 的真像素程序化推导。

## 一、上一版为什么"像素度不对、和素材差距大"（已定位，有证据）

用自写的 .aseprite 解码器（`tools/pixel_pipeline/aseprite_decode.py`）逐像素比对：

| 比对对象 | 结果 |
| --- | --- |
| `16x32 Walk-Sheet.png` ↔ `16x32 Walk.aseprite` | **20/20 帧逐位完全一致（0 差异）** → 模板 PNG 是忠实导出 |
| `star1.png` ↔ `star1.aseprite` | **可见像素不一致：79 个 alpha 差异 + 187 个颜色差异**（另有 461 个全透明像素的 RGB 差异，不可见） |

**结论**：不是模板有问题，而是 `star1.png` 根本不是该 sprite 的真像素（另一次导出/另一次改动）。
上一版拿它当参考、再经 SD 重绘，必然漂移。**同一角色、同一姿势，只因参考图差了 187 个像素，AI 就画成了另一个人。**

解码器还踩过一个坑：Aseprite 的 cel 有两种布局（≤1.2 无 Z-index，≥1.3 多 2+5 字节），
且本项目文件的 cel 行序是**自上而下**（按规范写"自下而上"会得到上下翻转的图）。
现在两种偏移都自动探测，并用 PNG 导出做朝向校验（`flip_rows=False` 胜出）。

## 二、本版做法（零 AI）

`tools/pixel_pipeline/derive_sheet.py`，从 `star1.aseprite` 的 4 帧真像素出发：

| 方向 | 做法 |
| --- | --- |
| **down**（列 0） | **直接用 aseprite 第 0~3 帧，逐位一致，未做任何改动** |
| **up**（列 1） | 把脸部像素块（肤/腮/眼，x=12..20 y=12..19）用头发色 `#2475B5` 填掉 → 后脑勺 |
| **left**（列 2） | 脸块整体左移 4px 到头缘、隐藏远端那只眼、尾部裁 1 列用头发盖住 → 左侧脸 |
| **right**（列 3） | left 的水平镜像 |

走路帧用**同一索引的源帧**推导，所以四个方向的腿部动作完全一致。
色板 = 全部产出帧的并集（13 色），量化不会改动任何像素。

## 三、验证（都跑过，不是估计）

```
down f1..f4 vs star1.aseprite frame 0..3 : 0 px differ   ← 逐位一致
列朝向（肤色像素数）: col0=132(正面) col1=8(背面无脸) col2=132 col3=132
validate.py: 尺寸 128x128 / 128x32 PASS ｜ alpha 只有 0/255 PASS ｜ 13 色(≤24) PASS
             16+4 格非空 PASS ｜ 1px 留边：WARN 8 像素贴边（见下） ｜ OVERALL PASS
```

**关于那个 WARN**：源素材 `real_f1`/`real_f3` 的脚部本来就落到格子最后一行（y=31），
规范里"四周留 1px 透明边"是给 AI 出图防溢色的规则，**你自己的原画并不满足**。
我选择保留原样（宁可逐位一致，也不动你的像素）；若你要严格满足该条，
把 4 帧整体上移 1px 即可，代价是切掉脚底那 1px。

## 四、已知取舍

- **up / left / right 是程序推导（"作弊"画法），不是真正的 3D 旋转**。
  在 32×32 的二头身里这是像素游戏的常规做法，观感成立；要真侧面/真背面需要手绘。
- up 视图仍能看到头顶的红花（在背面它处于可见侧），若不需要可在 `derive_back` 里一并抹掉。
- left/right 的脸是"贴到边缘"的，脸型比真侧脸宽一点（已用 trim 收窄 1px）。
