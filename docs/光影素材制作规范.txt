2D 光影素材制作规范
==================

一、总体约定
------------

1. 游戏可见画面使用 2D Sprite；3D 低模只用于阴影和空间遮挡计算。
2. 2D 贴图、Normal、Specular、Occlusion 和 3D 代理必须使用相同的建筑占地尺寸与地面基准。
3. 建筑当前只处理正俯视下可见的正面墙，旋转暂不启用。
4. 不得把动态太阳、月亮或灯光阴影烘进颜色图、法线图或 Occlusion。


二、Aseprite 图层
-----------------

layer
    地面占地、素材定位和对齐参考。

wall
    正面墙贴图。

roof
    屋顶贴图。

interior
    屋内贴图。

canwalk
    屋内导航标记：
    - 绿色 #4EC737：可行走区域
    - 紫色 #E351D0：交互区域

light
    局部灯具和扩散范围标记。

portal
    门窗入口标记。

其他图层
    仅作为绘制参考，不进入游戏运行时。


三、墙面和屋顶贴图
------------------

1. wall 和 roof 必须分开导出。
2. 墙面和屋顶应具有独立、尺寸相同的法线图。
3. 建议同时提供 Specular 和 Occlusion。
4. 同一层的颜色、法线、高光和 Occlusion 必须同尺寸、同原点、同 UV。
5. 窗框、门框、百叶窗、木板、砖缝和小招牌使用 Normal + Specular 表现。
6. 屋檐下、门廊下、窗洞、墙角等固定遮蔽使用 Occlusion 表现。
7. 屋檐、门廊顶和墙面小装饰不进入动态阴影代理。

建议文件名：

wall.png
wall_n.png
wall_s.png
wall_o.png

roof.png
roof_n.png
roof_s.png
roof_o.png

其中：
    _n = Normal
    _s = Specular
    _o = Occlusion


四、法线规范
------------

1. 使用固定切线空间法线。
2. 必须统一绿色通道方向，不得在不同素材中混用 OpenGL 和 DirectX 约定。
3. 法线朝向必须与正面墙或屋顶的实际朝向一致。
4. 角色左右翻转时，法线 X 方向必须同步翻转。
5. 非等比缩放素材时必须保留或重新计算正确的法线。
6. 不得使用颜色图的透明边缘挤压法线细节。


五、局部灯光标记
----------------

1. 使用 light 图层绘制局部灯具。
2. 蓝色标记表示灯具位置。
3. 黄色线表示灯光衰减到零的方向和半径。
4. 标记必须保持纯色，不使用抗锯齿边缘。
5. 每个独立灯具应能映射到外部 JSON 配置。

外部 JSON 配置至少包含：

    id
    世界位置或局部位置
    light_color
    energy
    radius_px
    height_px
    receiver_layers
    shadow_enabled
    on_hour
    off_hour

默认灯光层级：

    高层路灯：
        可照屋顶、墙面和地面

    店门口灯、低墙面灯：
        只可照墙面和地面，不可照屋顶


六、门窗 portal 标记
--------------------

1. 使用单独 portal 图层。
2. 每个门窗绘制为一条单像素高的水平标记线。
3. 标记中心表示门窗位置。
4. 标记水平长度表示门窗开口宽度。
5. 不需要绘制系统计算出的柔光长度和范围。
6. 不绘制扩散箭头。
7. 不得把多个门窗连成同一个连通区域。

暂定类型颜色：

    窗户：
        #4FA9FF

    玻璃门：
        #B06BFF

    普通门：
        #FF9A3C

普通门规则：

    1. 画面中始终绘制关闭门板。
    2. 不向屋内透光。
    3. 不产生夜间外泄光；窗户光由系统按门窗标记的宽度和高度生成贴合窗体的柔边方块。
    4. 可作为动态阴影代理的一部分。


七、portal 外部 JSON
--------------------

1. 门窗位置和宽度以 Aseprite 标记为准。
2. 外部 JSON 保存稳定 portal_id、类型、室内灯组和参数覆盖。
3. 每个标记必须匹配唯一 JSON 条目。
4. 不允许重复使用 portal_id。
5. 标记中心、宽度与 JSON 不匹配时必须报告错误。
6. window 和 glass_door 必须绑定存在的室内灯组。
7. solid_door 不绑定外泄灯组。

最低字段建议：

    id
    type
    marker_center_local
    width_px
    sun_transmission
    interior_light_group
    leak_strength


八、3D 低模阴影代理
-------------------

1. 每个可投影资产单独提供低模代理。
2. 默认轴心位于占地矩形的水平中心。
3. 地面高度为 Y=0。
4. 不得把建筑摆放位置、世界旋转或世界位移烘进代理。
5. 2D 素材绘制原点与 3D 代理轴心应分开记录。
6. 代理尺寸、朝向和地面基准必须与 2D 素材一致。

建筑代理应保留：

    建筑主体
    主要屋顶
    大型墙体结构
    会参与真实遮挡的主要体量

建筑代理不应保留：

    窗框
    门框
    百叶窗
    木板和砖缝
    小招牌
    屋檐
    门廊顶
    无法形成明显阴影的微小装饰

门窗不需要在低模代理上制作真实几何开口；屋内太阳光由 portal 标记生成。

树木代理：

    保留树干和主要枝冠轮廓。
    不需要逐叶细节。
    可以使用软阴影和轻微模糊掩盖减面缺陷。

路灯代理：

    保留灯柱和主要灯头轮廓。
    灯具自身不得阻挡其全向光，需要在运行时处理光源偏移或自遮挡。

角色代理：

    玩家提供独立动态低模。
    游客可以使用低模或简化胶囊体。
    代理高度、脚底位置和 2D 角色必须一致。


九、贴边与透明区域
------------------

1. 颜色图和法线图必须保留相同的透明边缘。
2. 透明区域不能残留无关颜色或法线数据。
3. Sprite 外扩透明边不应改变实际占地中心。
4. 墙脚和建筑正面边缘必须有清晰的世界坐标基准。
5. 大面积透明边不得用来隐式调整位置。


十、导出和验收清单
------------------

每个建筑至少检查：

    [ ] layer、wall、roof、interior、canwalk、portal 图层存在
    [ ] wall 与 roof 已分离
    [ ] wall_n 与 roof_n 存在
    [ ] Normal、Specular、Occlusion 尺寸与原图一致
    [ ] 所有图使用同一原点和 UV
    [ ] portal 标记类型和颜色正确
    [ ] portal 标记未互相粘连
    [ ] portal_id 与外部 JSON 一一匹配
    [ ] 每个可透光 portal 已绑定室内灯组
    [ ] 普通门画面为关闭状态
    [ ] light 图层灯具位置和黄色半径有效
    [ ] 3D 代理轴心位于占地水平中心
    [ ] 3D 代理地面位于 Y=0
    [ ] 3D 代理未烘焙世界位置或旋转
    [ ] 2D 与 3D 的占地宽度、深度和高度一致
    [ ] 代理中没有屋檐、门廊顶和小装饰
    [ ] 动态阴影只来自允许的代理结构


十一、当前明确不做
------------------

1. 不在低模上制作真实门窗开口来模拟室内太阳光。
2. 不使用屋檐和门廊顶产生动态阴影。
3. 不烘入动态太阳、月亮或灯光阴影。
4. 不在第一版实现建筑旋转。
5. 不在第一版让玩家、游客和家具遮挡门窗柔光。
6. 不使用固定窗格形状；门窗光使用柔边扩散。
