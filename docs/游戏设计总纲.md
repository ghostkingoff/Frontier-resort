# 边境度假村 · 游戏设计总纲

> 实现进度见 [开发进度.md](开发进度.md)。当前已完成 Phase 0 与 Phase 1 首版可玩闭环。

> 项目代号：边境度假村（Frontier Resort）
> 引擎：Godot 4.7　｜　首发平台：PC（Steam）+ 移动端　｜　商业模式：买断制

---

## 一、游戏定位

- **类型**：2D 像素 · 斜角俯视 · 沙盒经营模拟 + 文字事件式探险
- **一句话**：在奇幻边境从零建起一座度假村——白天经营扩张，夜晚深入荒野搜集珍贵物资。
- **平台**：PC（Windows / Steam）与移动端（iOS / Android）内容一致，不分拆
- **语言**：中文首发，架构预留多语言
- **内容体量**：目标体验时长约 30 小时，无结局沙盒；探索最深处是终极目标
- **美术**：2D 像素；一格 32×32，基准分辨率 1920×1080；带斜角俯视；屋顶可开关
- **美术来源**：优先购买现成素材 → 没有合适素材则定规格由作者绘制 → 必要时 AI 生成

**经济设定**

- 货币单位 **g**（金币），界面统一显示成 `12,000g` 这样
- 客人消费按现实中国物价的约 **10 倍**：一顿饭 450g、杂货 350g、住宿 1200g、诊疗 600g、展厅收藏消费 3000g
- 建筑造价：小型建筑约 **30000g**（杂货铺 28000、小木屋/招待厅 30000、烤肉店 32000、酒吧 35000），中型 60000~70000，大型珍品展厅 **100000g**
- 开局资金 35000g，够盖一栋小型建筑 + 铺一些路
- 客流：基础约 34 秒来一位客人，设施越多、口碑越高来得越密（最快 10 秒一位）；夜里继续经营时再降速到 1/2.6
- 实测节奏（正式参数、只带起始 3 栋建筑）：每天约 36~38 位客人、营业额 23000~24000g；一栋小型建筑约等于一天收入，新建筑回本约 4~6 天
- 其它数值同步 ×10：员工日薪 400~1000g、属性升级 3000~8000g、病症诊疗费 400~3800g、物资价值 120~36000g、灰石收购 30g/块

**度假村知名度**

- 独立于「口碑」的第二个声望数值，显示在顶栏第二行；**初始 100**
- **每天结算**：每接待一位游客 +1、明星额外 +10~20、日常自然 **-1**
- **明星 / 富商的到访概率**：知名度 ≤500 时为 0；之后按饱和函数上升，约 1000 时到 19%，**无论多高都不超过 20%**
  `p = min(20%, 20% × (1 - e^(-(知名度-500)/150)))`
- 口碑门槛仍然生效（例如白霜需要口碑 20）

**游客标签体系**

- 三组互斥标签：
  - 停留：**单日**（只来一天，不入住） / **多日**（住几天）
  - 人数：**单人** / **双人** / **三人**
  - 身份：**普通游客** / **明星** / **富商**；带明星或富商标签的不会同时是普通游客，但**明星+富商可以共存**
- 双人 / 三人：**共享一份预算**，满足离开条件后**一起离开**；平时约 80% 的概率**同进同出**（一起去同一家店或同一个闲逛点），约 20% 概率分头行动
- 普通游客：没有特殊效果
- 明星：预算极高（100 万起）、消费频率高、最多住 5 天、不会花完才走；给度假村带来知名度；到访概率受**知名度与口碑**影响
- 富商：预算多、消费多、最多住 5 天；不带来知名度；大量购买展厅物品；到访概率受**知名度与展厅展品总价值**影响

## 二、核心循环

1. **白天**（游戏内一天 = 现实 15 分钟，实时流动、可暂停）
   建造与升级建筑、雇佣员工、管理展厅物资、观察顾客与营收。
2. **结算与存档**：白天走完自动结算收益，并自动存档。
3. **选择**：休息，或外出探索。
4. **夜晚探索**（独立界面，不消耗游戏内时间）
   从低危区向高危区递进，通过文字事件做选择，搜集珍贵物资。
5. **回到白天**：物资用于提升自身属性、建造与升级建筑、打造消耗品、放进展厅寄卖，或低价销往内陆。

## 三、世界观与经济链条

**背景**：主角独自来到边境，靠搜集珍贵物资贩卖起家。卖得好之后在附近修了路，这一带开始有了客流，主角由此产生了建度假村的想法。边境只要不往极深处走基本安全，而边境特有的奇幻远景与天空本身就足以吸引客人。

**链条**：

- 游客主要由度假村吸引而来（设施等级、口碑、风景）。
- 特殊展厅展示的珍贵物资越多、越稀有，越容易吸引富商与明星。
- 每位游客自带预算与喜好；心情越高，消费越接近预算；特殊游客的消费可以超过预算。
- 普通商店 / 餐厅 / 医院等设施自动运转，玩家只需建造、升级、雇人。
- 特殊展厅有空间上限，玩家决定展示哪些物资、各展示多少件，不需要定价。
- 滞销与低价值物资可以低价销往内陆，作为兜底处理手段。

## 四、系统清单

### 1. 地图与建造

- 格子式放置，整体对齐整齐，便于规划道路与人流。
- 道路、地砖、植被等装饰约 10 余种。
- 地图可扩建，但有上限。
- **屋顶开关**：关闭屋顶后可以看到店内顾客数量与状态（休息 / 消费）；店内事务无需玩家管理。

### 2. 建筑种类与升级

当前规划：

| 类别 | 数量 |
| --- | --- |
| 度假屋 | 3 种 |
| 餐饮 | 6 种 |
| 商店 | 2 种 |
| 医院 | 2 种 |
| 休闲娱乐设施 | 5 种 |
| 其他设施 | 5 种 |
| 合计 | 约 23 种（后续持续增加） |

- 升级提升：可容纳顾客上限、消费额、消费后的心情加成。
- 医院升级：可接纳的病症类型增加。
- 部分建筑的建造与升级需要消耗探索所得物资。

### 3. 员工

- 工资固定，员工有状态值。
- 客流量越大，员工状态消耗越快。
- 若某店员工状态全部过低，顾客消费后心情会下降——高客流店铺需要多雇人。
- 医院特殊：可花高价雇佣更好的医生，治病更快、能治的病症更多。

### 4. 顾客（逐个模拟）

- 每位顾客带一份**总预算**和初始心情来到度假村；他们不会消费一次就走。
- 行为链：**进入 → 招待厅办理入住 → 度假屋分配房间 → 四处消费 / 回房休息 → 预算或心情见底 → 回招待厅结账 → 离店**。
- 离开条件（满足其一）：预算少于 300g（视为花完）、心情低于 25、住满该房型允许的晚数上限。
- **度假屋**：只负责入住，不按「进店一次」收费；住宿费按实际住的天数在**结账时**结算进账（最少 1 晚）。分三种：
  - **普通度假屋**（25,000g，1 人）——最便宜，只能住单人
  - **自然风度假屋**（60,000g，2 人）——能住双人，心情加成更高
  - **现代风度假屋**（120,000g，3 人）——最贵，能住三人，住宿费最高
  - 双人 / 三人组会**自动挑房位够的度假屋**入住
- **度假屋与招待厅不需要雇员工**，也不会因为没员工影响客人心情
- **作息**：白天客人都在外面活动（消费或闲逛），**只有晚上（24:00-06:00）才进度假屋休息**，天亮再出门。
- **闲逛**：客人不会一直消费——每段行程后约有 1/3 概率在村里随便找地方闲逛、发呆，然后才决定下一个去处；刚去过的店会先跳过，避免在两家店之间反复横跳。
- **招待厅**：全天开放，负责办理入住与结账；没有招待厅或没有空房时，客人只能当日往返。
- 每位顾客每一天都在花钱：一顿饭、一次购物、一晚住宿都从同一份预算里扣。
- **特殊游客**：富商、明星等，预算显著高于普通游客。
- **生病机制**：客人生病后 **12 小时（游戏内）**内得不到治疗就会直接离开、不再回来；治好之后回到行程里继续住。
- **作息**：夜里睡在度假屋直到早上 6 点；白天也会偶尔回房歇一会儿（约 20% 概率）。
- 心情受等待时间、拥挤程度、员工状态、环境等因素影响。

### 5. 探索

**世界地图**

- 每次出发随机生成一张世界地图：由方块地形拼成，形状不规则、有缺口，最下方是出发点。
- 地形四种：森林、沼泽、巨型蘑菇地、荒地（`data/terrains.json`，可扩）。
- 进入某个地形会点亮它和它周围的方块；没点亮的地方显示为 `?`。按 M 键随时查看大地图。
- 方块之间按上下左右相连，走到方块边缘就能朝对应方向出图 —— 出图方向与大地图上的方位一致。

**局部移动**

- 进入一个地形后，看到的是这个地形的局部格子图（同样是不规则分布）。
- 点击相邻格子移动：没走过的格子消耗 2 点体力，走过的消耗 1 点。
- 每次移动有概率触发文字事件；事件可能给物资、给灰石，也可能消耗 SAN。

**过渡区**（跨地形时）

- 十字形 5 格：入口 / 中间空地 / 出口 / 帐篷 / 商人位。
- 出图方向决定入口位置（往左出图，就从过渡区右边进入），出口在对面一格。
- 帐篷：二选一，休息（体力 +3）或冥想（SAN +2），每次过渡只能用一次。
- 商人：40% 概率出现，是一个理智的怪物，收灰石、给物资。

**灰石**

- 探索中从地里捡到的特殊资源，荒地最多。
- 带出边境会造成不好的影响，所以回家时由边境军队按 3 金/块低价收走。
- 也可以在过渡区跟商人换物资。

**风险规则（当前只做低危区）**

- 低危区：体力或 SAN 见底 → 自动回家，收获保留。
- 后续的高危区计划：体力见底丢掉全部收获；SAN 见底或被怪物抓住 → 游戏结束，读回探索前存档。
- 最深处：属性满值才能进入；首次进入获得成就道具，之后高概率获得稀有物资。

### 6. 属性与成长

- **探索向**：体力上限、SAN 上限、采集效率、运气等。
- **经营向**：议价能力、声望、审美等——影响游客数量、特殊游客到访概率与售价。
- 珍贵物资的用途：提升自身属性、建造与升级建筑、打造消耗品（回复体力、恢复 SAN、照明、护身等）。

### 7. NPC 与剧情

- 轻量背景故事，**无强制主线**。
- NPC 与对话系统：内陆商人、其他探险者、常客等。
- 前期用少量引导性对话带玩家理解玩法与背景，中后期完全自由。

### 8. 存档

- 每天白天结束、结算收益时自动存档。
- 进入探索前再存一个存档点。
- 探索死亡 → 读回探索前的存档。

### 9. 平台与发行

- 买断制，PC 与手机内容一致。
- Steam 成就 + 云存档；移动端本地存档（云备份可选）。
- 手柄适配（PC，中后期）。
- 触摸操作：点击建造、双指缩放、拖动地图。

## 五、技术架构（Godot 4.7）

- **数据驱动**：建筑、物品、顾客类型、病症、探索事件、对话全部用配置表（Resource / JSON）描述，扩充内容不改代码。
- **目录结构**：`scenes/`（场景）、`scripts/`（逻辑）、`data/`（配置）、`art/`（美术）、`audio/`、`ui/`、`docs/`。
- **时间系统**：全局时钟统一驱动，支持暂停与倍速；白天 15 分钟映射游戏内 12 小时。
- **顾客模拟**：状态机 + 网格寻路；分帧更新与距离分级，控制手机端同屏人数。
- **输入抽象**：鼠标与触摸统一为指针事件，一套逻辑两种操作方式。
- **存档**：序列化保存；"每日存档"与"探索前存档"分开管理。
- **本地化**：翻译表形式，中文首发。
- **性能目标**：手机端同屏顾客 80 人以上、稳定 60 帧（实测后调整）。

## 六、开发路线图（12 个月）

| 阶段 | 时间 | 内容 | 交付 |
| --- | --- | --- | --- |
| Phase 0 | 第 1 周 | 项目骨架、目录结构、美术规格文档、分辨率与输入适配 | 可运行的空框架 |
| Phase 1 | 第 1–2 月 | 格子地图、相机缩放拖动、建造放置、时间系统、2–3 种建筑、顾客进出消费、白天结算存档 | **核心闭环可玩版** |
| Phase 2 | 第 3–4 月 | 员工、建筑升级、医院与病症、特殊展厅、内陆倾销、经济报表 | 经营系统完整版 |
| Phase 3 | 第 5–6 月 | 体力 / SAN、低危到高危探索、事件系统、死亡读档、属性成长、消耗品打造 | 探索系统完整版 |
| Phase 4 | 第 7–8 月 | NPC 对话与背景故事、全部建筑与地砖、UI 打磨、音效音乐 | 内容完整版 |
| Phase 5 | 第 9–10 月 | 移动端适配与触摸操作、性能优化、平衡性、成就、云存档、多语言 | 平台就绪版 |
| Phase 6 | 第 11–12 月 | 内测、Bug 修复、商店页面、宣传素材、提审 | 发行候选版 |

每个阶段结束都会留一个可上手试玩的版本。

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| 逐个模拟顾客在手机端性能吃紧 | 分帧更新、路径缓存、同屏人数上限、距离分级 |
| 30 小时内容量与一年周期的矛盾 | 全面数据驱动 + 建筑模块化拼装 + 素材复用 |
| 美术工作量 | 占位素材先行，购买 / 生成 / 自绘三路并行，规格先定死 |
| 探索死亡带来的挫折感 | 高危区入口明确预警、可随时回撤、存档点前置 |
| PC 与手机 UI 差异 | 一套 UI 两套布局，指针事件统一输入 |

## 八、待确认的补充提议

以下为建议项，先按此实现，随时可改：

1. **倍速功能**：白天提供 1x / 2x / 4x 与暂停。
2. **季节与天气**：预留接口，首发只做轻量天气（影响顾客心情）。
3. **建筑外观随等级变化**：做，升级需要视觉反馈。
4. **地图结构**：一张可扩建的大地图，分区逐步开放。
5. **多语言**：中文首发，英文预留。
6. **音频**：先用免费与生成素材占位，后期替换或购买。
