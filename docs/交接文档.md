## 一、项目与运行

- 项目：`E:\godot\模拟经营类`（Godot 4.7，2D 像素，PC + 手机买断制）
- **引擎路径**：`E:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe`（不在 PATH 里）
- 打开方式：Godot 导入 `project.godot` → F5。主场景是 `scenes/title.tscn`（标题界面）
- 冒烟测试：`godot --headless --path . -- --smoke`（**自动使用独立存档目录 `user://saves_test`，绝不碰玩家存档**）
  - 想用完全测试模式跑一遍：加 `--mode=full_test`
- 平衡测量：`res://tools/balance_check.tscn -- --days=3`（64 倍速跑几天，打印每日营收）
- 存档体检：`res://tools/save_check.tscn -- --slot=1`；截图工具：`res://tools/screenshot.tscn -- --screenshot`（只读不写存档）
  - 截图工具想看完全测试模式铺满建筑：加 `--mode=full_test --view=shelves`
- 住客作息专项体检：`godot --headless --path . -- --wake`（陆续醒来 +「休息一晚」位置重置，14 项一次跑完）
- 文档索引：`docs/游戏设计总纲.md`（设计）｜`docs/开发进度.md`（已实现）｜`docs/待办与小问题.md`（问题清单 + 清理记录）

> **跑测试的小坑**：Godot 把日志写到控制台句柄，`> 文件` 重定向会得到 0 字节的空文件。
> 想抓日志用 `2>&1 | Out-String` 或在 PowerShell 里用 `Start-Process -RedirectStandardOutput`。
> 另外脚本一旦有解析错误（Parse Error），冒烟测试不会失败退出，而是**永远挂着不结束**——
> 超时卡住时第一件事是看 stderr 里的 `Parse Error`。

## 四、✅ 10-07 那批改动 + 本轮验证

上一轮命令行组件故障，23 栋新建筑那批改动「写完但没验证」。本轮已全部跑通并补了回归覆盖：

1. `data/buildings_extra.json`：23 栋新建筑（餐饮 8 / 商店 3 / 医院 3 / 休闲 6 / 其他 3），带 `unlock_fame` 解锁知名度
2. 建造菜单按知名度显示「（知名度 XXX 解锁）」并置灰；建造系统也拦一道；**知名度变化后菜单会自动刷新**（本轮新修）
3. 公共卫生间（不消费只涨心情）、**保洁工人**（雇人才出现，在外面走动清扫，负责半径 40 格）、共享单车（速度 ×2.2）
4. 垃圾：每位客人平均 48~72 游戏小时留一个；附近垃圾持续掉心情（每个 -0.35 心情/游戏小时）
5. 度假屋三种：基础（60,000g，4×4，1 人）、自然风（150,000g，6×6，2 人，知名度 300）、现代风（260,000g，6×6，3 人，知名度 300）
6. 招待厅在入口旁 (64,62)；旧烤肉店/杂货铺标记 `hidden` 不再显示

**本轮额外修掉的真问题**

- `title_screen.gd` 在 `_ready()` 里直接 `change_scene_to_file()` 会报 `Parent node is busy adding/removing children`：改成 `call_deferred`
- 建造菜单只在构建时算一次解锁状态，置灰项永远不变灰 → 抽出 `_refresh_build_list()`
- `staff_slots` 为 0 的自助设施（卫生间/共享单车）仍吃「缺员工 -14 心情」和「没有员工」提示 → 新增 `Building.is_self_service()`
- 两份建筑表同名 id 静默覆盖 → 新增启动时的一行提示（`food_bar`、`clinic_small` 是有意保留的，见下）
- 保洁间原来只是「每 2.5 秒自动清掉附近垃圾」，看不出有工人在干活 → 改成**保洁工人 NPC**，见下

**保洁工人（`scripts/customers/janitor.gd`，10-08 新增）**

- 保洁间本身不扫地，它按**员工数**生成对应数量的保洁工人：雇 1 位出现 1 位，解雇 / 拆除时工人消失
- 工人会在度假村里自己找垃圾 → 走过去 → 走到跟前清掉；也会在负责范围内随机溜达
- **负责范围 = 以保洁间为中心半径 40 格**（`ROAM_RADIUS_CELLS`），范围外的垃圾不会去清
- 常量都在 `janitor.gd` 顶部：`ROAM_RADIUS_CELLS`、`SPEED`（62 像素/秒）、`SEARCH_INTERVAL`
- 工人挂在 `World/Staff` 层下（开了 y 排序，会被建筑正确遮挡）
- 注意：这个脚本**没有用 `class_name`**，一律用 `preload("res://scripts/customers/janitor.gd")` 引用——
  新加的 `class_name` 不在引擎的全局类缓存里会直接编译失败
- 踩过的坑：`roam_radius()` 一度只返回格数却拿去跟像素距离比较（范围缩成 1 格）；
  `walkable_path_cells()` 的缓存会在铺地/盖楼时被清空，取模前必须重新取并判空（否则偶发 `Modulo by zero`）

**已知的数据「陷阱」（改之前先看这条）**
- `data/buildings.json` 与 `data/buildings_extra.json` 有 2 个同名 id：`food_bar`、`clinic_small`。
  扩充表那份生效（酒吧 3×3 / 小型诊所 3×2），主表那两条 `hidden` 且名字带「（旧）」，
  **只为了让旧存档还能解析出老建筑，不要删、也不要改 id**。启动时会打印一行说明。
- 早期「扩充建筑统一长宽各 +1」的规则已经从代码里删掉，尺寸直接写在 `buildings_extra.json` 里。

**已知的无害告警**：退出时 Godot 会打印 `resources still in use`（标题 BGM 的 ogg），无害。

## 四、开发约定（重要）

- 每次改动都跑 `--smoke`；**动到开局配置就两种模式各跑一次**；测试写 `user://saves_test`，**永不读写玩家存档 `user://saves`**；截图工具只读
- 数值尽量放 `data/*.json`，不要藏在代码里
- 涉及存档结构的改动，除新档外还要用旧档读一次验证兼容性（玩家存档槽 1 是 10-07 的旧档，可以直接用来试）
- 64x 倍速是测试档，发布前删除（`GameClock.Speed.X64`、HUD 的 64x 按钮与 KEY_4）
- **写 GDScript 记得给 `world.xxx()` 这类无类型返回值标注类型**：`var dirty: int = world.litter_near(...)`。
  不标注会直接 `Parse Error: Cannot infer the type`，而脚本加载失败时冒烟测试是「卡住」而不是「报失败」
- **开发工具不经过标题界面**：冒烟测试与截图工具是直接实例化 `main.tscn` 的，`pending_mode` 是空的。
  所以任何「新游戏时才生效」的初始化都要能在这种情况下也跑起来（本轮是靠 `--smoke` / `--screenshot` 判定开发工具模式），
  否则会出现「代码明明写了、跑起来却没生效」
