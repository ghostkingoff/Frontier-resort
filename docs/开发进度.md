**用 Godot 编辑器（推荐）**

1. 打开 Godot 4.7
2. 导入项目 → 选择 `E:\godot\模拟经营类\project.godot`
3. 按 F5 运行（主场景已经设好，直接进游戏）

```powershell
& "E:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe" --path "E:\godot\模拟经营类"

## 二、当前已实现

**主界面与存档**

- 游戏启动先进入标题界面：开场短动画（幕布淡出 + 场景缓慢推进 + 标题浮现），点任意位置可跳过
- 主菜单三项：**新游戏 / 读取存档 / 设置**
- **新游戏有两种开局模式**（在存档面板上方切换）：
  - **初始模式**：知名度 100，9 栋建筑（招待厅 + 三种度假屋 + 小餐馆 + 小超市 + 酒吧 + 小型诊所 + 珍品展厅），门口小路已接好。正式玩用这个
  - **完全测试**：资金 **99,999,999g**、口碑 **200**（上限）、知名度 1000，建造菜单里全部 29 栋建筑都已建好并自动接好路，
	员工招满，每种物资各 1000 件。用来快速验证各个系统
	- 布局：建筑全部摆在**主街上方的三条横街**里（y=38 / 27 / 16，矮的在下、高的在上），
	  左右两条竖路（第 4 / 122 列）把三条横街连通；**建筑不压任何路面**，中间主干道永远是通的
  - 命令行也能指定：`godot --headless --path . -- --smoke --mode=full_test`
  - 建筑数据不带开局模式；模式只在「新游戏」生效，读档一律以存档内容为准
- 存档类似星露谷：3 个存档位，每个槽是一局独立的游戏；标题界面能看到每个槽的「第几天 / 资金 / 设施数 / 游玩时长」，可以覆盖或删除
- **每天 24 点结算时自动保存**到当前存档位；探索前会另存一个探索前存档点（`slot_N_explore.json`）
- 游戏内按 ESC 打开菜单：继续游戏 / 保存进度 / 回到主菜单
- 设置：主音量、音乐、音效、全屏；保存在 `user://settings.cfg`
- 主场景是 `scenes/title.tscn`，点新游戏或读档后切到 `scenes/main.tscn`
- 存档只保存游戏进度（天数、资金、建筑、仓库、属性…）；「一天多长」「倍速」这类设计参数不写进存档，读档时永远用当前版本的设定
- 自动化测试写到独立目录 `user://saves_test`，不会碰玩家存档

**时间与经营**

- 全天 24 小时连成一条时间轴：06:00 → 24:00 → 次日 06:00（24 小时 = 现实 24 分钟，即游戏内 1 小时 = 现实 1 分钟；白天夜里流速一致），空格暂停
- 倍速：1x / 2x / 4x，另有一个 **64x 测试档**（在顶部信息栏最右侧，正式发布前删掉）
- **一天只结算一次**：24 点自动暂停并结算（营业额、到访人数、口碑），自动存档；早上 6 点不再弹结算，夜里 0-6 点的收益会并到下一次 24 点一起算
- 结算时三个选择：休息一晚（自动结算夜间收益并直接跳到次日 6 点）、外出探索（同样自动结算，回来就是早上 6 点）、夜晚继续管理
- 夜晚继续管理：从 24 点顺着同一条时间轴走到次日 6 点，只有夜间店铺接客；客流量按「开门店铺 × 知名度系数 × 口碑系数」每小时对账，夜里店铺少、人数自然下降
- F 键跳过：白天按 F 跳到 24 点结算（仍然可以选夜晚继续管理），夜里按 F 跳到次日 6 点结算
- 夜里顾客、员工、治疗都会正常推进（之前夜里会停住）
- 店铺有开业时间：普通店铺 06:00-24:00，边境酒吧 22:00-04:00（`data/buildings.json` 的 open_hour / close_hour）
- 选择休息或探索时，夜间营业的店铺会按估算自动结算一次收益
- 资金、天数、口碑、设施数量显示在顶部信息栏

**地面与通行**

- 地面分三种：普通草坪（默认，不可通行）、可行走草坪（可通行）、地砖（可通行）
- 顾客只走地砖和可行走草坪，按网格寻路（四方向，不穿建筑）
- 建造菜单最上方「地面」：铺地砖 3 金/格、铺可行走草坪 1 金/格、恢复普通草坪 1 金/格，按住左键可以连着刷
- 地面全部由玩家自己铺（没有自动铺路）：起始地图自带一条主路、一条支路和两条通往起始建筑的小路
- 连不上主路的店铺不会有客人，建造时会直接提示哪些店连不上；建筑面板里也会红字提示“客人过不来”
- 顾客从主路两端进场，沿小路走到店门口；因为要绕路，一个人来回比以前久，单位时间到访人数会少一些

**拆除建筑**

- 建造菜单顶部新增「拆除建筑」工具：点建筑选中（红色高亮并显示返还金额），再点一次确认拆除，ESC 取消
- 建筑面板底部也有「拆除建筑」按钮，同样需要点两次确认
- 返还**投入的一半**（建造成本 + 已花的升级费用）
- 展厅里展示的物资会退回仓库；店里的顾客 / 病人会被请出去；地基与铺好的地面保持不变

**度假村围墙与入口**

- 建造区四周有围墙（底边中间留出入口，正对主路与支路），墙体不可通行、也不能铺地面
- 入口内侧是「招待厅」（其他设施分类，可升级）：客人一进门先到这里落脚，能补一点心情
- 起始地图自带主路、支路和通到小木屋 / 烤肉店 / 招待厅的小路

**建造**

- 格子式建造（一格 32×32 像素），半透明预览，绿色可放 / 红色不可放
- **建筑分两张表**：`data/buildings.json` 是原始 9 栋，`data/buildings_extra.json` 是扩充的 23 栋（两处同 id 时报错提示，见下）
- 共 31 种建筑，建造菜单里显示 29 种（`food_grill` 边境烤肉店、`shop_general` 杂货铺标记 `hidden` 已淘汰）
- **知名度解锁**：建筑可以带 `unlock_fame`，玩家知名度不够时菜单里显示「（知名度 XXX 解锁）」并置灰，建造系统也会拦一道；知名度涨上去后菜单会自动刷新成可点
- 扣钱、占地校验、与已有建筑冲突校验

**顾客**

- **标签化游客名册**：`data/customers.json` 定义了三组标签（停留 / 人数 / 身份）和 **276 组带名字的客人（共 409 个名字，其中 204 个外国名字 ≈50%）**；中文名统一「正常起名后去姓」，双/三人组按一家人取名（共用字），例如「有田 + 秀兰」「长河 / 长云 / 长星」；外国名按语区取材，例如「Elizabeth」「Seraphina + Dorian + Cecilia」「Winston」「Aurelia」
- **有空房就优先来住宿客**：抽新客人时，只要还有走得通且住得下的度假屋，就 85% 概率从
  「多日 + 这间房住得下」的池子里抽（`LODGE_PRIORITY_CHANCE`），其余走普通池；
  每小时的补人目标也会加上**空房位总数**（`free_room_people()`）——入住客人不计入客流量，正好补前期人气
- **游客不重复出现**：抽新客人时跳过「已经在村里」的名册条目（含住店 / 就诊 / 正在离场），明星富商同样适用
- **明星 / 富商到来提示**：进场时弹一条金色、持续 3 秒的提示（含名字；双人 / 三人组列出全员）
- **游客状态面板**（顶栏按钮）：右侧**分两栏**「普通游客」「明星 / 富商」，上方按钮切换；每行 = 正面头像 + 名字，点名字 → 相机对焦 + 橙色中括号高亮，并显示该客人的状态 / 心情 / 已消费 / 同行伙伴（没有伙伴不显示这行）；**再点一次名字 / ESC / 顶栏按钮**都退出对焦，相机停在原地
- 双人 / 三人共享预算、满足条件一起离开（`scripts/customers/party.gd`）
- 知名度初始 100，每天结算：游客按人头 +1、明星 +10~20、日常 -1；明星/富商只在知名度 >500 后按概率到访（1000 时约 19%，上限 20%）
- 到访人数按人头统计（双人组算 2 位）；同行小组约 80% 时间同进同出
- 逐个模拟的**住客**：带预算进场 → 招待厅办入住 → 度假屋分配房间 → 循环「挑设施 → 走过去 → 消费 / 回房休息」→ 预算见底或心情低于 25 → 回招待厅结账 → 离店
- 度假屋收入按住宿天数在**结账时**产生（最少 1 晚）；招待厅全天开放并显示累计办理入住次数
- 客人类型带 `max_nights`：边境居民 0 晚（当日往返）、游客 2、家庭 3、收藏家 2、富商 3、明星 5；预算 2,000 ~ 50,000g
- 一间度假屋同时只住 1 位客人；客人白天在外消费 / 闲逛，只有晚上回房休息
- 度假屋分三种，都不需要雇员工：**基础度假屋（60,000g，4×4，1 人）、自然风度假屋（150,000g，6×6，2 人，知名度 300 解锁）、现代风度假屋（260,000g，6×6，3 人，知名度 300 解锁）**；双人 / 三人组会自动挑房位够的入住
- 白天也偶尔（约 20% 概率）回房歇一会儿；夜里则睡到第二天早上
- **早上陆续醒来**：住客在 **06:30~07:30 之间各自随机一个时间点**起床（`customer.gd` 的 `WAKE_EARLIEST` / `WAKE_LATEST`），不是 6 点整集体弹起来；06:00~06:30 之间没人会出门
- 结算面板选「休息一晚」时，会把场地上的顾客位置统一重置：**有房间的住客直接回房睡觉**（回来时已经是第二天早上），**当日往返的客人在夜间收益结算之后直接离开**，不会留在场地里空走
- 客人有约 1/3 概率在村里闲逛（随机找个可通行格子待一会儿），并且不会连续去同一家店
- **垃圾与心情**：客人平均每 48~72 游戏小时留下一个垃圾（只落在可通行格上，最多 400 个）；附近有垃圾时客人持续掉心情，每个垃圾额外 -0.35 心情/游戏小时
- 地图尺寸 **128×80 格（早期版本的 4 倍）**，横向主街 + 中央大道 + 各店门前小路
- 新档初始配置：**9 栋建筑**（招待厅、基础/自然风/现代风度假屋、小餐馆、小超市、酒吧、小型诊所、珍品展厅），全部已接通主街，进游戏就能测试所有系统
- 走路用四方向贴图：素材是「列 = 方向、行 = 走路帧」，程序按这个规则取帧
- **视角风格：开罗式正面视角**——NPC 始终正面朝镜头（只播走路帧，移动时带轻微小跳步），建筑用正面立面。等补上侧向素材后，把 `customer.gd` 里的 `FRONT_FACING_ONLY` 改成 `false` 就会恢复「按移动方向切换朝向」
- 6 种顾客类型（居民、游客、家庭、收藏家、富商、明星），各自有预算与偏好设施，高级顾客需要口碑解锁
- 消费金额受建筑等级、顾客预算、心情影响，消费时弹出金币数字
- 顾客在店里时进入建筑的内部视图，关闭屋顶即可看到

**画面**

## 三、Phase 2 已完成（经营深度）

**员工**

- 每栋建筑可以雇佣 / 解雇员工，工资固定（按建筑类型，日结）
- 员工有状态值，客流量越大掉得越快；每天开盘前休息恢复
- 员工全部状态过低（或一个人都没雇）→ 客人消费后心情下降，消费变少
- 医院可以花钱请更好的医生：治疗更快、同时接诊更多病人

**建筑升级**

- 点建筑打开面板，可看到升级所需资金与探索物资
- **最大同时招待人数：1 级 3 人，每升一级 +1**（`capacity_base` / `capacity_per_level` 可在建筑数据里覆盖；
  路灯这类不接客的设施写 `capacity_base: 0`，永远不会被客人选中）
- **使用位 / 预定位（排队）双位系统**：
  - **使用位**（1 级 3 个，每级 +1）：客人**走到店铺 5 格以内才真正占位**（`reserved`）——
	远处来的路上不算占位，空位不会被长期占着；进店时转成正式占位，消费完才空出来
  - **预定位**：5 格内抢使用位**被抢先**就顶到预定位，走到**门口那一列排队位**站着等
	（状态显示「在 XX 门口排队等位」）；使用位一空，**队首自动顶上**进店。选址先找有空使用位的店，
	都没有才去排队。放弃 / 改道 / 离场都会把两种位子还回去（客人销毁时还有兜底清理）
  - 建筑详情会显示「同时招待 x / y 人（在途 n）」
- 升级后平均消费、心情加成也提升；医院还能治疗更多病症
- 探索物资不足时，按钮会直接写明缺少什么

**医院与病症**

- 6 种病症，分 1~3 级；诊所等级决定能治哪些病（1 级治不了跌伤与边境热）
- 客人生病后会走向能治病的诊所排队、接受治疗并付诊费，口碑上升
- **生病后每次做决定都优先去能治的诊所**（挑下一站、被同伴拉走时都会先试）；村里没有能治的医院就照常消费 / 闲逛，
  不会原地站着不动——玩家中途盖起 / 升级医院，客人下一站就会去看病
- 治疗时限 **6 游戏小时**（`deadline_hours`）：走路 / 消费 / 排队都在倒计时，到点还没治上就带病离开、口碑下降；
  只有「正在治疗」不计时
- **生病概率**：`base_chance` 0.007、`crowding_chance` 0.0024（原值的 20%）

**珍品展厅**

- 有展示位上限（随等级提升），玩家自己决定展示哪些物资、各多少件
- 展示的物资按稀有度累计“吸引力”，越多越容易吸引收藏家、富商与明星
- 每天结算时随机成交，成交价高于倾销价，口碑也会上升

**内陆倾销**

- 仓库面板里可以按 35% 价格把滞销物资卖给内陆商人（单件卖 / 全部卖）

**存档与开始菜单**

- 启动时出现开始菜单：继续游戏（读取最近自动存档）/ 新游戏
- 存档包含资金、天数、口碑、仓库物资、每栋建筑的等级 / 员工 / 展厅陈列

**临时机制（探索系统开放后替换）**

- 已关闭：探索系统现在负责提供物资。`GameState.placeholder_night_yield` 保留为测试开关

### 7.1 建筑的出入口：外圈一圈都能进，但优先走门口

`Building` 提供三个东西（`scripts/world/building.gd`）：

| 成员 | 含义 |
| --- | --- |
| `door_cell()` / `door_point()` | 贴图上门口那一格／那个点，**只是首选**，不再是唯一出入口 |
| `perimeter_cells()` | 占地四周各向外一格的整圈格子（例如 3×2 建筑 = 20 格） |
| `entry_point()` | 首选入口的世界坐标，供朝向与距离判断 |

`World` 据此选入口（`scripts/world/world.gd`）：

| 函数 | 用途 |
| --- | --- |
| `best_entry_cell(b, from)` | 优先门口；门口不可走或走不通时，从外圈里挑**能真正算出路**的最近一格；都没有返回 `(-9999,-9999)` |
| `nearest_entry_cell(b, from)` | 从建筑里往外走时用，规则同上（不看连通性，只看可通行） |
| `building_reachable(b)` | 外圈任意一格通就算可达 |

顾客侧（`scripts/customers/customer.gd`）：

- `_entry_cell` 记住本次要走的入口，行走与到达判定都用它（不再写死 `door_point`）
- `_start_cell_candidates()` 在从建筑里出来时，把该栋楼**所有出入口**当候选（门口排第一），
  逐个试到「能走 + 能算到目标」为止 —— 只在真有路时才移动，否则会把角色挪到另一个走不出去的地方
- `_recover_if_no_path()`：该走路却没路径超过 1.5 秒就重新决策（路线被新建筑压住、缓存过期等）

> 改动前客人只认门口那一格：门口没铺路或被人占了，这栋楼就整栋不可达。
> 现在只要外圈任意一面通着就能进，但门口仍然优先，玩家的直觉（把路铺到门口）依然有效。

### 7.2 走位代码共用一个基类

`scripts/actors/actor.gd` 是「会走路的角色」基类，`customer.gd` 与 `janitor.gd` 都继承它：

| 基类提供 | 子类覆盖 |
| --- | --- |
| `_start_path_to()` / `_follow_path()` / `_step_towards()` / `_update_animation()` | `_walk_speed()`（顾客会被共享单车改速） |
| `_check_stuck()` 的通用卡住判定 + `_build_sprite_base()` | `_anim_fps()`（顾客 8 帧/秒、保洁 7 帧/秒） |
| `clear_path()` / `has_path()` / `reset_stuck_timer()` | `_is_standing_still()`（保洁只在 MOVING 时才算卡住） |
| 常量 `CELL` / `DIR_*` / `FRONT_FACING_ONLY` | `_fix_start_cell()`（顾客要从所在建筑门口走出来） |
| 变量 `world` / `sprite` / `speed` / `_path` | `_on_stuck()`（顾客会重新算路、闲逛或离场） |

> 注意：子类**不要重复声明**基类已有的成员（如 `world`），GDScript 会直接报
> `The member "world" already exists in parent class`。

#### 相机手感参数（都在 `camera_controller.gd` 顶部，可直接调）

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `min_zoom` / `max_zoom` | 0.7 / 2.8 | 缩放范围（原 1.0 / 4.0，两端各 ×0.7） |
| `middle_drag_max_speed` | 2550 | 中键按住时贴到屏幕边缘的速度（原 1700，+50%） |
| `drag_accel_rate` | 9.0 | 平移速度追赶的平滑速度，越大越跟手 |
| `glide_decay_held` | 28.0 | 鼠标停下但还按着时的速度衰减，**越大惯性越弱** |
| `glide_decay_released` | 10.4 | 松手后的惯性滑行衰减，同上 |
| `pan_ramp_rate` | 5.0 | 「移动视口」按钮模式的起步 / 收尾平滑速度 |
| `glide_min_speed` | 4.0 | 低于此速度直接停，避免无限缓慢漂移 |

> **调惯性的公式**：指数衰减下「总滑行距离 ≈ 初速 ÷ 衰减率」，即**距离与衰减率成反比**。
> 想让滑行减半就把衰减率乘 2；想让滑行翻倍就除以 2。别去改 `drag_accel_rate`，那改的是跟手程度。
> 当前 `glide_decay_*` 是最初 7.0 / 2.6 的 4 倍，滑行约为最初的 1/4。
>
> 平移统一走 `_glide`（世界像素/游戏秒）这一层：所有输入只改「目标速度」，
> 实际位移由 `_glide` 指数平滑追上去。因此**中键和按钮模式共用同一套惯性**，
> 起步不突兀、松手会滑一段再停。
> 实测：起步 0.05 秒走 5 像素 → 稳定后 874 像素；松手后总滑行约 131 像素后完全停住。
> 注意 headless 下 `warp_mouse()` 无效（鼠标固定 0,0），测相机位移要把 `limit_*` 临时放大，
> 否则一帧就撞到边界、位移被夹掉，会误判成「惯性没生效」；
> 另外**必须累计「从松手到停住」的总位移**，只测松手后 0.05 秒会被起步冲量主导、测不出衰减变化。

### 7.6 夜晚光照与店铺灯光（10-08）

**光照分两层**，这是理解这套系统的关键：

| 层 | 节点 | 作用 |
| --- | --- | --- |
| 全局压暗 | `Daylight`（`CanvasModulate`，脚本 `scripts/world/daylight.gd`） | 按 `data/lighting.json` 的关键帧给整个画面染色 / 压暗 |
| 局部提亮 | `PointLight2D` | 店铺灯光。**`CanvasModulate` 只能整体变暗、无法局部变亮**，所以「周围一圈变亮」必须靠点光源 |

#### 灯光形状与层次（关键）

**层次顺序：地板 → 灯光 → 屋顶/外墙。**

| 子节点顺序 | 内容 | 说明 |
| --- | --- | --- |
| 1 | `Interior`（地板 + 墙边框） | 最底层 |
| 2 | `NightLight`（挂在 World 下） | 中间层，照亮地板 |
| 3 | `Exterior` / 各面 | 最上层，开屋顶时把地板和灯光一起盖住 |

`building.gd` 的 `_relayer()` 负责这个顺序（不能靠添加顺序，因为 `_build_visuals` 先建了外墙）。
**原来的顺序是「外墙 → 地板 → 灯」，地板反而盖在灯上面，光进不去** —— 这就是「地板遮挡光照」。

**灯光尺寸 = 建筑占地 + 每边 1 格**（1 个渐变带）。纹理比例 **平顶区 : 渐变带 = 1 : 0.5**，
所以 `纹理全宽 = 平顶区宽 / 0.667`。实测 4×4 建筑：光斑 192px、外圈正好 1 格。

> **曾经的 bug：光斑比建筑大 3~4.5 圈。** 原因是纹理取了 1:1，而代码又按 `1/0.5` 把
> 「占地 + 1 格」翻倍去算纹理全宽，等于把光斑放大到「占地 + 4 格」。
> 改纹理比例为 1:0.5 并直接用「平顶区 = 占地」反推全宽后修正。

#### 实测剖面（小超市，垂直向下）

| 区域 | 亮度 |
| --- | --- |
| 建筑上方（外部） | 33~63 |
| **室内** | **199~227（均匀）** |
| 墙边框 | 59.7 |
| **外圈渐变** | 174 → 167 → 139 → 99（约 1 格） |
| 远处 | 79.7（不受影响） |

> **`PointLight2D` 的 z 范围坑（最隐蔽的一个）**：它默认的 `range_z_min/range_z_max`
> 只覆盖很小的 z 区间，而建筑的 `z_index = int(position.y)`（可达 2000+）。
> 灯若挂在建筑下面就会继承这个大 z、掉出范围，**完全不参与渲染**——
> 表现为「纹理有、energy 有、visible=true、参数全对，但画面毫无变化」。
> 解决：`make_rect_light` 里把 `range_z_min/range_z_max` 设为 ±8192，
> 灯挂到 World 根并用 `global_position` 定位（不要挂在建筑下）。

**让屋顶盖住灯光**：灯挂在 World 下就不再受建筑的绘制顺序影响，
所以把灯的 `z_index` 压到 **-4000**，让地面/建筑画在它上面 —— 开屋顶时屋顶自然盖住灯光。

> 注意 Godot 的 `z_index` 合法范围是 **[-4096, 4096]**。写 -100000 会刷
> `Tried to set Z index to an invalid value` 且**设值失败**（顺序也不受控）。

**灯的定位**：`cell_center(cell)` 已经是建筑左上格的**中心**，所以
建筑中心 = `cell_center(cell) + (footprint - 1) * 0.5 * CELL`。
曾经多加了半个占地，导致光**偏向右下**。

**通用光源工厂**：`World.make_rect_light(inner_size, spread, color)`。
后续加路灯 / 移动光源都走这个接口，只要给出「要均匀照亮的中心矩形」和「渐变带宽度」，
形状与渐变口径就自动一致。建筑的灯就是这么建的（`building.gd` 的 `_build_lights`）。

> **Godot 4 的 `PointLight2D` 三个 API 坑：**
> 1. `texture_scale` 是 **float（等比缩放）**，不是 `Vector2`。
>    要非等比（矩形）得用「`texture_scale` 定宽 + 节点 `scale.y` 补高」组合。
> 2. **没有 `centered` 属性**（那是 `Sprite2D` 的），它总是以纹理中心为原点。
> 3. 默认 `range_z_min/range_z_max` 装不下建筑的 z_index（见上）。

**行为**：20:00~20:45 之间各栋建筑**陆续**亮起（`light_on_hour` 每栋随机），
**常规店 24:00 打烊后在 24:00~24:30 之间陆续熄灭**（`light_off_hour` = 打烊 + 0~0.5 小时随机）；
酒吧（22:00→04:00）与路灯亮到 04:00 按点熄。

> **跨夜店必须换算成「连续小时」再比较**：`hour_of_day()` 是 0~24 口径，
> 但酒吧 `close_hour()=4` 小于开灯时间 20，直接写 `hour >= 20 and hour < 4` **永远不成立**，
> 跨夜店会整晚不亮。统一处理：
> - 凌晨（`hour < 12`）当作「前一天 24 点之后」→ `hour += 24`
> - 跨夜打烊（`close < open`）→ `close += 24`
>
> 这样普通店与跨夜店都变成简单的区间判断，不需要特判。
> 实测 02:30 的实景：常规建筑全暗、**只有酒吧亮着**，符合预期。

### 7.5 寻路网格改成了增量更新（10-08）

**先测出来的事实**（`tools/perf_probe.tscn`，128×80 = 10240 格）：

| 操作 | 优化前 | 优化后 |
| --- | --- | --- |
| A\* 全量重建一次 | 5.46 毫秒 | 5.46 毫秒（保留为兜底路径） |
| `set_ground` 自身 | 0.002 毫秒 | 0.002 毫秒 |
| **连续铺路（每格 + 寻路）** | **5.45 毫秒/格** | **0.008 毫秒/格** |
| `place_building` | 6.47 毫秒 | 1.01 毫秒 |
| 6 位客人 `_process` | 0.04 毫秒/帧 | 0.04 毫秒/帧（本来就不是瓶颈） |

结论：**AI 和寻路本身极快，唯一的瓶颈是「改一格就全量重建 10240 格」。**

做法：`World._astar_dirty_cells` 只登记改动过的格子，`_ensure_astar()` 优先走增量分支
（`set_ground` 登记 1 格、`_mark_occupied` / `remove_building` 登记占地的那些格）。
「直接置脏」仍保留全量重建作为兜底。

> **两个坑，改这块之前务必知道：**
> 1. **新建的 `AStarGrid2D` 默认所有点都可通行**，必须在创建时立刻按地图填一遍。
>    只置 `_astar_dirty = true` 就进增量分支的话，脏格表是空的、会直接返回，
>    网格永远是全空 = **客人能穿过建筑**（实测 10240 格里 9488 格状态是错的）。
> 2. 增量更新漏标记一格，网格就会过期、同样导致穿墙，而普通玩法测试**很难发现**。
>    所以冒烟测试里常驻了 `寻路网格同步` 检查：逐格对比「增量结果」与「全量重建结果」，
>    必须为 0 格不一致。**新增任何改动可通行性的代码，都要记得调 `_mark_astar_cell()`。**
