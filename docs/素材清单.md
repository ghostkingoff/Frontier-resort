# 边境度假村 · 素材清单

> **这份清单是「要做什么」的唯一来源**：人工美术和 AI 生成两份规范都引用它。
> 追加新素材时**只需要往下加行**，不要改动已有行的编号。
>
> 配套文档：`素材制作规范_人工.md`（人工制作用）｜`素材制作规范_AI生成.md`（AI 生成用）
>
> 最近更新：10-08 ｜ 基准规格：**原生 32×32 像素 / 格**，1920×1080 基准，最近邻缩放

## 〇、怎么用这份清单

- **编号**：`类别-名称`，全小写英文 + 下划线。已有行的编号不要改（代码和文档都引用它），新素材往后加。
- **优先级**：
  - **P0** 核心可玩性，正式美术第一批必须做完
  - **P1** 完整体验，第二批
  - **P2** 锦上添花 / 可延后
- **状态**：`占位`（现在是临时代码／现成素材包）｜`待做`｜`已完成`｜`已替换`
- **现有**列 = 当前用的是什么占位素材，替换时对照着看。

## 十一、追加新素材时怎么做

1. 在对应章节**表格末尾加一行**，编号按 `类别-名称` 规则取，不要复用已有编号。
2. 把尺寸、优先级、状态、现有占位填上。
3. 如果新素材引入了**代码目前不支持的结构**（比如多朝向建筑、带帧动画的设施），在规范文档里补一句，
   并提醒改代码 —— 光有贴图代码是不会用的。

**当前已经知道「代码还不支持、需要一起改」的点**：

- 建筑目前只有**正面视角**一套贴图；若要四朝向或 3/4 视角，要动 `building.gd` 的 `THREE_QUARTER_VIEW` / 取图逻辑
- `faceset.png` / `portrait.png` 目前**没有任何代码读取**
- `interior_floor` 代码按「占地×16 再放大 2 倍」裁切，改成 32px 原生地板要同步改 `building.gd:157`
- `SPRITE_SCALE = 2.0` 共被 **6 个文件、8 处**引用：`data_registry.gd:5`（定义）、
  `customer.gd:118`、`janitor.gd:59`、`building.gd:161`、`build_system.gd:125`、
  `world.gd:318`、`world.gd:320`、`title_screen.gd:102`。
  正式素材按 32px 交付后，把定义改成 `1.0` 即可，但 `sprites.json` 里 decorations 的 `rect` 尺寸
  是按现在的显示尺寸写的，需要一起核对
- 装饰素材的 `rect` 尺寸与 `SPRITE_SCALE` 是**耦合**的（现在 16px 素材 × 2 倍 = 表里显示的尺寸）；
  换成 32px 原生素材时必须同时把 `SPRITE_SCALE` 改成 1.0，否则会放大成 2 倍大小
