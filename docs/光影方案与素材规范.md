# 2D 光影方案与素材规范

素材制作要求已单独整理为：`docs/光影素材制作规范.txt`。

## 一、总体方向

- 游戏画面继续使用 2D Sprite。
- 光照和阴影可以使用 3D 低模代理计算，但最终只合成到对应的 2D 层级。
- 不再用一张全屏光照图覆盖所有表面。
- 地面、墙面、屋顶、屋内和角色分别使用自己的法线、接收遮罩和受光 shader。
- 相机保持正俯视，不旋转；当前只处理建筑正面墙。
- 所有贴地效果必须按斜角俯视做纵向压缩，共用
  `shaders/lighting_v2/ground_projection.gdshaderinc`；不可直接使用正面圆形效果。
- 建筑旋转数据接口保留，但功能暂不实现。

## 二、层级与光源规则

### 显示层级

- 地面层
- 屋内层
- 墙面层
- 屋顶层
- 角色层
- 标签和 UI 不受光影影响

### 灯光层级

- 太阳、月亮：最高层，可照屋顶、墙面和地面。
- 普通路灯：当前只照亮地面，不覆盖玩家、游客或建筑贴图。
- 路灯光池使用地面专用光层；玩家仍由 Normal 材质计算局部受光。
- 路灯旋转只改变灯具外观，不改变椭圆光池中心，也不改变 3D 灯光方向。
- 路灯默认从 `18:00` 点亮，持续到次日 `08:00`。
- `ligh1t.png` 只作为形状示意，不直接叠加到场景。运行时以路灯底座为圆心生成轴对齐的柔边椭圆地面光池。
- 路灯地面影子读取角色 3D 脚底代理：影子沿灯池中心到角色的径向向外拉伸，越靠近中心越短；角色与中心重合时保留一个宽度等于代理宽度的接触椭圆。
- 店门口灯、低墙面灯：低层光，可照墙面和地面，不可照屋顶。
- 室内灯：只照屋内层和屋内角色。
- 墙后光源不能照亮或投影到正面墙。
- 天空散射始终为正面墙保留少量底色。

### 视口筛选

- 太阳和月亮始终参与。
- 局域灯的影响范围与“视口世界矩形 + 128px”相交时才参与。
- 进入使用 128px 外扩，离开使用 160px 外扩，以减少边界闪烁。
- 相机移动只重新采样光照，不重复计算未变化的静态世界阴影。
- 静态建筑和树木阴影可缓存。
- 动态角色阴影优先更新最近、最重要的灯。
- 初始压力测试目标为动态角色阴影更新前 8 盏灯，使用 8/12 名滞回。

## 三、阴影规则

- 阴影由低模代理、光源和世界空间几何求交产生，不复制 Sprite。
- 地面和正面墙共享同一低模代理、光源和时间。
- 玩家与墙壁阴影代理以玩家脚底为地面原点。
- 墙面影子允许真实的斜射压缩、倾斜和透视。
- 墙面影子拉伸达到 `1.5` 倍后开始逐渐淡出，`2.5` 倍时消失；数值可调。
- 墙面只接收灯前侧的影子。
- 墙脚使用少量重叠和柔边衔接，不允许硬切或断开。
- 阴影使用线性采样、软阴影和模糊，不做像素化阴影。
- 墙面与地面共用同一张 3D 阴影图。墙面按离墙脚的高度朝太阳方向取样，墙脚高度为零，因此墙面与地面阴影在交界处使用同一采样点。
- 墙面投影最大偏移为 `160px`，但更早受 `1.5→2.5` 倍拉伸淡出约束；屋顶保持独立遮挡，不接收墙面投影。
- 屋檐、门廊顶、窗框、门框和表面小装饰的阴影由 Normal + Occlusion 静态表现，不进入动态阴影代理。
- 上述装饰不向墙面或地面投射动态阴影。
- 建筑主体、主要屋顶、树木、路灯、玩家、游客和大型家具可进入阴影代理。

## 四、屋内太阳与月光

- 正常营业建筑允许太阳通过窗户和玻璃门进入屋内。
- 门窗入口光使用柔边扩散，不显示清晰窗格。
- 入口方向跟随太阳，夜间不产生月光入口光。
- 门窗光只影响屋内层和屋内角色。
- 第一版不处理玩家、游客和家具对门窗光的动态遮挡；它们只参与法线受光。
- 入口光白天随太阳淡入淡出。
- 普通门始终关闭：画面也是关闭门板，不透太阳光，也不产生外泄光。

## 五、夜间窗户

- 夜间窗户不再向屋内提供月光入口。
- 室内灯只照亮屋内层和屋内角色。
- 窗户会向屋外产生暖色外泄光，形状严格贴合窗体的方形轮廓，边缘在窗体内柔和衰减。
- 外泄光只覆盖窗体本身，不向墙面或地面扩散。
- 外泄光跟随每扇窗绑定的室内灯组开关。
- 外泄光不产生阴影，不反向照亮屋内。
- 外泄光使用约 `0.1～0.2` 秒现实时间快速淡入淡出，不受游戏倍速影响。
- 店铺默认从 `18:00` 起在 `18:00～18:45` 内错峰开灯，从 `24:00` 起在 `24:00～24:30` 内错峰关灯。
- 当前所有室内灯组统一跟随建筑营业时间，但保留逐窗灯组绑定作为未来扩展。

## 六、门窗标记

- 使用单独的 Aseprite `portal` 图层。
- 每个门窗绘制为一条单像素高的水平标记线。
- 标记中心代表门窗位置，标记长度代表开口宽度。
- 系统根据太阳方向和门窗宽度自动计算柔光长度与边缘扩散。
- `portal` 图层只负责位置、宽度和类型。
- 外部的建筑 JSON 保存稳定门窗 ID、室内灯组和参数覆盖。
- 每个标记必须匹配唯一 JSON 条目；缺失、重复或位置不匹配时直接报告错误。

暂定类型标记色：

- 窗户：`#4FA9FF`
- 玻璃门：`#B06BFF`
- 普通门：`#FF9A3C`

普通门需要同时保存标记，但透射率和外泄强度均为零。

## 七、Aseprite 图层约定

- `layer`：地面占地和定位参考。
- `ground`：建筑外围地形装饰层；使用地面光照材质，仅在屋顶视图显示。
- `wall`：正面墙贴图。
- `roof`：屋顶贴图。
- `interior`：屋内贴图。
- `canwalk`：绿色为可行走区，紫色为交互区。
- `light`：局部灯具位置和范围标记。
- `portal`：门窗柔光入口标记。
- 其他图层仅作为绘制参考，不进入运行时。

墙面和屋顶可使用同一画布尺寸，但必须导出独立贴图和独立法线。

建议配套文件：

```text
wall.png
wall_n.png
wall_s.png
wall_o.png

roof.png
roof_n.png
roof_s.png
roof_o.png
```

其中 `_n` 为法线，`_s` 为高光，`_o` 为 Occlusion。

## 八、法线与 Occlusion 规则

- 法线使用固定切线空间约定，绿色通道方向必须在素材规范中明确。
- 颜色图、法线、高光和 Occlusion 必须同尺寸、同原点、同 UV。
- Normal 负责随光源方向变化的 N·L 与高光。
- Occlusion 主要衰减天空环境光和间接光，直射光只适度使用。
- 建筑旋转后，墙面、屋顶、法线和灯光标记必须使用同一旋转。
- 屋檐、门廊和墙面细节通过 Normal + Occlusion 表现，不额外制作动态投影网格。

## 九、3D 低模代理

- 每个资产独立提供不显示本体的阴影低模。
- 默认轴心位于占地矩形水平中心。
- 地面高度为 `Y=0`。
- 不烘焙世界位移、建筑摆放位置或最终建筑旋转。
- 只需保留建筑主体、主要屋顶、主要结构体积和必要的大型可投影结构。
- 不制作窗框、门框、木板、砖缝、百叶窗、小招牌等细节。
- 屋檐和门廊顶可不制作，因为它们不参与动态阴影。
- 门洞、窗洞不需要通过真实几何开洞实现室内太阳光；室内太阳由门窗标记光模拟。
- 松树等自然物体保留主要枝冠轮廓，细节可由软阴影和模糊掩盖。
- 玩家和游客需要独立动态低模代理。
- 2D 素材、法线和低模代理必须使用一致的占地宽度、高度和地面基准。

## 十、性能目标

- 目标分辨率：`1920×1080`
- 目标场景：30 盏真实阴影路灯
- 目标帧率：稳定 60 FPS
- 必须同时检查 1% Low、GPU 帧时间和阴影任务积压
- 必须测试相机平移、缩放、日夜切换和多名角色移动
- 所有候选灯都参与照明；动态角色阴影只优先更新最近、最重要的灯

## 十一、后续待调参数

- 门窗入口光强度、最大长度和柔边范围
- 夜间外泄光强度、颜色和方形柔边宽度
- 太阳墙面阴影 `1.5/2.5` 拉伸淡出阈值
- 动态角色阴影更新灯数量及 8/12 滞回范围
- 法线、Occlusion、高光和阴影的合成比例
- 不同建筑类型的灯光组与营业时间扩展
