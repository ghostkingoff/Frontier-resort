# 待办与小问题清单

> 用法：把想到的问题随手写进下面的表格，不用整理。每次阶段收尾时统一清一遍，
> 由我来判断“现在改便宜”还是“以后改也没事”。

## 判断规则

## 开发约定（重要）

- **测试一律使用全新存档**：`--smoke` 跑测试前会自动清空 `user://saves_test`，每一次都是新开的档
- **玩家存档目录 `user://saves` 开发工具绝不读写**：测试写 `saves_test`，截图工具只读不写（`SaveManager.read_only`）
- 改动涉及存档结构时，除了新档，也要专门用旧档读一次，确认兼容性（例如之前「旧存档带回旧时间参数」就是这么发现的）

| 类型 | 典型例子 | 以后改的成本 | 处理方式 |
| --- | --- | --- | --- |
| 数据 / 数值 / 文案 | 建筑价格、顾客预算、事件消耗、病症数值、按钮文字 | 几乎为零（改 `data/*.json`） | 攒着，阶段收尾时一起改 |
| 界面布局 / 手感 | 面板位置、按钮大小、相机缩放、提示文字、结算排版 | 低（改一处 UI 代码） | 可拖，但最好在内容变多前定稿 |
| 规则 / 结构 | 存档内容、格子尺寸与美术规格、顾客行为方式、时间轴结构、属性体系 | 越往后越贵 | 尽早改 |

需要早改的四件事：**美术规格**、**存档结构**、**顾客行为方式**、**UI 操作范式**。
