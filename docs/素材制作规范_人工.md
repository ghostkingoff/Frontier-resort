# 边境度假村 · 素材制作规范（人工）

> **给谁看**：接这个项目的美术（外包或自己画）。
> **配套文件**：`docs/素材清单.md`（要画什么、优先级、尺寸）｜`docs/素材制作规范_AI生成.md`（给 AI 的版本）
>
> **画之前请先读完第一节和第二节**——第一节的尺寸写错会导致素材进游戏被拉伸变形；
> 第二节是这个项目的画风基准，跟你以前做过的项目可能不一样。
>
> 最近更新：10-08 ｜ 基准：**原生 32×32 像素 / 格**

## 一、技术规格（硬性，写错的素材会被打回）

### 1.1 像素基准

| 项目 | 数值 | 备注 |
| --- | --- | --- |
| 一格 | **32×32 像素** | 所有尺寸都以格为单位换算 |
| 建筑贴图 | **占地格数 × 32** | 严格相等，多一像素少一像素都会被拉伸 |
| 角色单帧 | **32×32** | |
| 物资 / UI 图标 | **32×32** | 画布 32×32，图形居中 |
| 地面图块 | **32×32** | 必须四方无缝 |
| 基准分辨率 | **1920×1080** | 相机默认 1.3 倍缩放 |

> ⚠️ **不要再交 16×16 的素材。** 项目现在的占位素材是 16px 的，靠代码放大 2 倍显示；
> 正式素材按 **32px 原生**画，代码里的放大机制会退休。
> 如果你交 16px、代码没同步改，成品会是「大像素」观感（一个像素占 2×2 屏幕像素），画面会糊。

### 1.2 引擎侧的硬要求

| 要求 | 说明 |
| --- | --- |
| **最近邻缩放** | 项目全部素材使用 `TEXTURE_FILTER_NEAREST`，**不要做抗锯齿、不要羽化边缘** |
| **禁用半透明抗锯齿边** | 边缘要么全不透明要么全透明，半透明像素在最近邻下会出现杂色描边 |
| **贴图四周留 1px 透明边** | 防止相邻图块采样溢出（图集切片尤其重要） |
| **格式** | PNG，32 位 RGBA，**不要嵌入色彩配置文件**（导出时关掉 ICC / sRGB profile） |
| **颜色空间** | sRGB，不要 HDR / 不要线性化导出 |
| **不要预乘 Alpha** | 导出选项里关掉 Premultiplied Alpha |

### 1.3 切片与图集约定

- **角色**：一个角色一张 `walk.png` = 4 列 × 4 行（每帧 32×32，整图 128×128）。
- **方向列顺序写死在代码里，绝对不能改**：

  | 列 | 0 | 1 | 2 | 3 |
  | --- | --- | --- | --- | --- |
  | 朝向 | **下**（朝镜头） | **上**（背对） | **左** | **右** |

  代码常量：`DIR_DOWN=0, DIR_UP=1, DIR_LEFT=2, DIR_RIGHT=3`。
  历史上出过事故：贴图是「列＝方向、行＝走路帧」，但代码按「行＝方向」取帧，结果人物走路像在原地转圈。
  **交稿时请明确写清「列＝方向还是行＝方向」。**

- **建筑**：一张贴图对应一栋建筑，不做图集拼合（除了以后的批量优化）。
  贴图左上角对齐建筑占地的左上角，**不要留内边距**。
- **物资图标**：单文件，不拼图集。
- **地面**：拼成一张图集交给程序，图集内图块按 32×32 网格排列。

### 1.4 命名与目录

```
art/
├── tiles/          ground_atlas.png, nature_atlas.png, wall_tile.png
├── buildings/      bld_<id>.png         例：bld_food_diner.png
├── characters/     <角色名>/walk.png idle.png faceset.png portrait.png
├── items/          item_<id>.png        例：item_bar_copper.png
└── ui/             ui_<用途>.png        例：ui_icon_coin.png
```

- 全小写英文 + 下划线，**不要中文文件名、不要空格**。
- 建筑 / 物资的 `<id>` **必须和 `docs/素材清单.md` 里的编号一致**，代码靠这个找图。

### 1.5 交稿方式

1. 按上面的目录结构放好 PNG，**同时交 PSD / Aseprite 源文件**（后续微调要用）。
2. 只交 PNG 就行，**不要手动创建 `.import` 文件** —— 那是 Godot 导入时自动生成的。
3. 一批素材一次交，附一张「本次交了哪些编号」的清单，方便对照 `素材清单.md` 更新状态。

## 二、画风基准（项目自定义）

> 项目**不临摹任何现成素材包**（避免版权风险）。下面是这套项目自己的画风规则，
> 现在的 Ninja Adventure 素材只是临时占位，正式素材以本节为准。

### 2.1 一句话风格

**温暖明亮的像素卡通**：粗描边、色块分明、细节克制，像度假村的宣传画；
不是写实、不是暗黑、不是极简线条。

### 2.2 分类主色（这套色板是**接口**，请务必遵守）

建筑的屋顶与招牌要用所属分类的主色，玩家才能一眼分辨这栋楼是干什么的。
色值来自 `data/buildings.json`，**改色要同时改数据文件**：

| 分类 | 主色 | 色值 | 用在哪 |
| --- | --- | --- | --- |
| 度假屋 | 草绿 | `#8FBF6A` | 屋顶 |
| 餐饮 | 暖橙 | `#E0A04A` | 屋顶 + 招牌 |
| 商店 | 蓝 | `#5FA8D3` | 屋顶 + 招牌 |
| 医疗 | 红 | `#D96A6A` | 十字标志 + 屋顶 |
| 休闲 | 紫 | `#B58AD8` | 屋顶 + 霓虹 |
| 特殊 | 金 | `#D8B34A` | 展馆、贵重感 |
| 其他 | 灰蓝 | `#9AA7B4` | 招待厅、卫生间等市政设施 |

**每种分类给 3~5 个明度层次即可**（屋顶亮面 / 屋顶暗面 / 墙面 / 门窗），不要每栋楼配一套独立色板，
否则 30 栋建筑放在一起会花。

### 2.3 光照方向（重要）

- **光源固定在左上角**。所有素材的高光在左上、阴影在右下，**30 栋建筑要一致**。
- **不要在贴图里烘焙昼夜变化**。游戏里有全局光照（`CanvasModulate` 按小时变化，
  从清晨暖色 → 正午中性 → 傍晚橙 → 深夜蓝），
  贴图按**中性光**画，昼夜效果由引擎叠加。
- 阴影只在建筑自己身上，**不要画投影到地面的长影子**（会和地面图块打架）。

### 2.4 描边与线条

- **外描边 1px**，深色但不是纯黑 —— 建议 `#1A1526` 一类的深紫黑，比纯黑柔和。
- 内部结构线用同色系深色，不要用黑色硬描。
- **不要把描边画在贴图最外圈那一像素上**，留出 1px 透明边（见 1.2）。
- 像素艺术不要用「半透明渐变过渡」，用色阶跳跃做明暗。

### 2.5 比例与构图

- **建筑**：正面视角。主体占画面 2/3 高度，留出屋顶轮廓；
  **门必须在贴图底边正中**（代码用底边中心算客人的门口位置），门宽约 1 格。
- **角色**：Q 版，**2 头身**（头占身体一半），脚底落在格子中心偏下。
- **物资图标**：图形居中，四周留 2px 安全边；小物件（金币、钥匙）可以画大一点，
  但**画布仍是 32×32**，不要改画布尺寸。
- **地面图块**：均匀平铺纹理，**不要画明显的图案中心**，否则铺开后会出现规律性重复。

### 2.6 细节密度

- 32×32 里能塞的细节有限：**一栋建筑最多 3 个记忆点**（招牌、门窗、屋顶造型），
  其余用色块带过。宁可简洁，不要堆细节 —— 缩到实际显示大小时细节会糊成一团。
- **同分类的建筑要有辨识度差异**：小餐馆 vs 西餐店不能只靠招牌字不同，
  造型（层数、屋檐、露天座）要能区分。

## 三、逐类制作要求

### 3.1 建筑

**必须交两套状态**：

1. **外观态**（默认，`exterior`）：完整正立面，含屋顶。
2. **透视态**（玩家按 R 关屋顶后）：显示室内。

透视态的实现方式：程序会把建筑内部的底板（`bld-interior_floor`）和边框画出来，
**所以建筑贴图本身不需要画出「没有屋顶的样子」**，但需要保证：
- 建筑占地范围内是实心的（不要留透明洞），
- 室内地板的可平铺纹理要单独交一张（见清单 `bld-interior_floor`）。

**尺寸对照（摘自清单，以此为准）**：

| 占地 | 贴图尺寸 | 例 |
| --- | --- | --- |
| 2×2 | 64×64 | 奶茶店、公共卫生间 |
| 3×2 | 96×64 | 小餐馆、小超市、小型诊所 |
| 3×3 | 96×96 | 酒吧、中餐店、游戏厅 |
| 4×3 | 128×96 | 自助餐店、游泳池 |
| 4×4 | 128×128 | 基础度假屋、招待厅 |
| 6×6 | 192×192 | 自然风 / 现代风度假屋 |
| 5×7 | 160×224 | 珍品展厅（全项目最高） |

> 度假屋三种要**明显分档**：基础（朴素木屋）→ 自然风（原木藤蔓）→ 现代风（玻璃钢构），
> 价格差 4 倍多，外观必须让人一眼看出「这个更高级」。

### 3.2 角色

每个角色 4 张：`walk.png`(128×128)、`idle.png`(128×32)、`faceset.png`(64×64)、`portrait.png`(64×64)。

- **walk 的 4 帧要有明显的位移感**：手臂摆动 + 身体上下起伏 1px，
  不要 4 帧几乎一样（游戏里会看起来像在滑行）。
- **左右朝向要画成真正的侧面**，不要镜像正面 —— 镜像会让衣服上的图案反掉。
- **保洁工人**（`chr-janitor`）建议加围裙 / 扫帚 / 帽子的识别特征。
  现在代码是拿老人角色加了蓝色滤色，正式素材不需要滤色。
- **贵客 / 明星 / 富商**要有金饰、华丽面料这类一眼可辨的贵气元素。

### 3.3 物资图标

- 统一 32×32（现在占位图从 7×7 到 32×16 参差不齐，UI 里大小不一很乱）。
- **按品质分层**（`data/items.json` 的 `rarity`）：
  - 普通：朴素、单色
  - 稀有：加一点光泽
  - 传说（边境之心）：明显华丽，必须有独特轮廓
- **同类物品系列化**：6 种金属锭（铜/铁/银/金/紫金/秘银）要**同一个造型只换色**，
  玩家才能一眼看出这是「同一类东西的不同等级」。

### 3.4 地面

- 三种地面：**地砖**（可行走）、**可行走草坪**、**普通草坪**（不可行走）。
  视觉上必须能分辨「能不能走」—— 现在靠深浅区分，正式素材建议草坪用「平整程度」区分
  （可行走＝修剪过、不可行走＝杂乱带草簇）。
- 四方无缝：**交稿前请实际平铺 5×5 检查一遍**，有接缝会被打回。
- 过渡块（`ground-lawn_edge`）按 4 个方向各一张。

### 3.5 自然装饰

- 树、石、灌木、水塘。**注意你在画的尺寸是显示尺寸**（见清单第六节的表格），
  已含 2 倍关系，直接按表里的宽高画。
- 装饰会按 `y` 坐标排序，**树冠要比树干宽**，遮挡关系才自然。
- 地图边缘会用树线围一圈，所以树要能**无缝并排**。

## 四、验收流程

### 4.1 交稿自检（交之前自己过一遍）

- [ ] 尺寸和 `素材清单.md` 完全一致（**逐张量像素，不要目测**）
- [ ] PNG、32 位 RGBA、无色彩配置文件、无预乘 Alpha
- [ ] 最近邻放大 3 倍看一遍：没有半透明杂边、没有抗锯齿
- [ ] 地面图块平铺 5×5 无接缝
- [ ] 角色 walk.png 是 4 列 × 4 行，且**列＝方向**
- [ ] 建筑门在底边正中
- [ ] 建筑贴图无内边距，尺寸 = 占地 × 32
- [ ] 光源方向统一左上
- [ ] 同分类建筑主色符合第二节色板

### 4.2 进游戏后的验收（开发这边做）

素材放进 `art/` 后由开发跑：

```powershell
# 画面自检：会输出到 .tmp/ 目录，逐张看是否有拉伸变形
& "E:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe" `
  --path "E:\godot\模拟经营类" res://tools/screenshot.tscn -- --screenshot

# 完全测试模式：28 栋建筑全部摆出来看整体协调性
& "...godot.windows.opt.tools.64.exe" --path "E:\godot\模拟经营类" `
  res://tools/screenshot.tscn -- --screenshot --mode=full_test --view=shelves
```

**重点看图**：

- 建筑是否被拉伸（尺寸不对会立刻看出来）
- 30 栋放在一起是否协调（色板是否统一）
- 角色走路是否自然（帧序对不对）
- 与现有占位素材混用是否突兀（替换期会混用一段时间）

### 4.3 替换为正式素材时要改的代码

> 这一节是给开发的，美术只需知道「交 32px 原生素材是有前提的」。

1. `scripts/core/data_registry.gd:5` → `SPRITE_SCALE` 由 `2.0` 改 `1.0`
   （另有 7 处引用不用改，它们都读这个常量：`customer.gd:118`、`janitor.gd:59`、
   `building.gd:161`、`build_system.gd:125`、`world.gd:318`、`world.gd:320`、`title_screen.gd:102`）
2. `data/sprites.json` 的 `decorations` 各 `rect` 尺寸按新素材实际尺寸核对
3. `building.gd:157` 的室内地板裁切 `footprint × 16` → `footprint × 32`
4. `data/buildings.json` / `buildings_extra.json` 每栋的 `sprite.atlas` / `sprite.rect` 指向新图
5. 跑 `--smoke` 回归 + 截图目视

## 五、常见问题

**Q：我可以只交 16×16 吗？**
不建议。项目基准是 32×32 原生。交 16×16 就等于交回现在占位素材的效果（大像素观感）。

**Q：建筑可以画得比占地大一点（比如带个招牌凸出来）吗？**
不行。贴图会被拉伸到占地尺寸，超出部分会被压缩变形。需要凸出效果就画在占地范围内。

**Q：同一栋建筑升级后外观要变吗？**
目前**不要求**（升级只改数值）。如果以后想做外观变化，会单独加素材编号和代码支持。

**Q：为什么不要画投影？**
游戏里地面是独立图块，建筑投影会和地面图块、其他建筑重叠打架；而且全局光照会变，
固定投影会在夜里看起来很怪。

**Q：UI 现在全是代码画的色块，也要出图吗？**
可选（清单第八节标了 P2）。当前 UI 用 Godot 默认主题运转正常，出图是视觉增强，不是阻塞项。

**Q：不确定某个需求怎么办？**
先看 `docs/素材清单.md` 对应行的「现有」列，那里写了现在用的是什么占位素材，照着替换即可。
还是不确定就在交稿前问，不要猜着画完一大批。
